# E5: legend-observation control for a factorised value circuit (launched 2026-09-15)

**Status:** finished 2026-09-15; the control failed -- see RESULT below. The sections above it are the launch-time record.

## What was built

- `goalmisgen/envs/legend.py` defines `LegendEncoder`, a 12×12 observation with four channels:
  - 0 wall, 1 agent.
  - 2 objectives: both objectives on one plane, with no colour.
  - 3 legend: two marks in the padded border, at (r, 11) and (11, c), where (r, c) is the objective carrying feature 0. At rho = 1 that is the richer objective.
  - Values stay hidden and the level content is unchanged. The dataset fingerprint is identical, so `levels/values/1.00-0.50@1M` is reused.
  - A first-layer gain on plane 2 scales both objectives alike. The legend marks are never within a 3×3 kernel of the objective they name, so value has to be bound downstream.
  - `install()` / `install_on_import()` patch `MazeConfig.encoder`.
- `scripts/legend_site/sitecustomize.py` switches the legend on process-wide when that directory is on `PYTHONPATH`.
  - This reaches every stage (001, 013, value_axis_sweep, 014, restricted_writes, input_gain) with no script edits.
  - JAX is not imported at start-up.
  - A legend checkpoint (12×12) fails loudly if loaded without the hook.
- `tests/test_legend.py`: 10 tests, passing locally and on the pod.
- `scripts/pods/legend_chain.sh` runs the g1 recipe end to end:
  1. Train 150M steps.
  2. Decode the final checkpoint for convergence (argmax reaches ≥ 95%).
  3. If it has not converged, extend with the g1 tail-LR protocol (+100M at 4e-6, first converged checkpoint wins). The chain stops before the sweep if it still has not converged.
  4. Sweep o0/o1 at ±0.1..0.4, 400k-step arms.
  5. Run 014 o0/o1.
  6. `restricted_writes --sweep o1`.
  7. `input_gain --sweep o1`. Its labels "colour 0/1" mean plane 2 (objectives) and plane 3 (legend).

## RESULT (added 2026-09-15 ~21:50 UTC, from the session that ran E1–E6)

### Chain
- The 150M run reached an objective in only 14.4% of argmax decodes, so the tail-LR extension ran.
- Its checkpoints reached 13.6 → 18.5 → 35.8 → 92.4 → **99.8% at +62.5M**. The chain took that checkpoint (`legend11g1.s1234e/cp_62494720`), then ran both sweeps, 014, restricted writes and input gain. `E5_CHAIN_DONE` came at 18:45 UTC.
- One step printed "Error in sitecustomize: No module named goalmisgen", but every output file was written.
- **The reaper failed.** The pod's `runpodctl` is too old for `pod delete` ("unknown command pod"), so the pod sat idle from 18:56 to 21:45 UTC (~$2) until I deleted it by hand. Any future reaper must call the Surface's runpodctl, or `runpodctl remove pod`.

### Why the control is uninformative
The net is competent at navigation but **barely uses value**.

| | legend11g1.s1234e | colour base novalue11g1.s1234 |
|---|---|---|
| base τ (task optimum 10) | **0.9** | 6.9 |
| fine-tuned slope, steps per unit value (task 20) | **≈1.6** (v 0.1 → 1.8, v 0.9 → 0.5) | 14–16 |
| axis held-out R² | 0.02–0.11 | ~0.6 reliability |
| full axis written at ±0.3 | τ 1.5 / 0.5 (CIs overlap base) | 12.2 / 4.4 |

It behaves as a nearest-objective agent with a weak tilt towards the legend. The fine-tuned arms move τ by about a step across the whole value range. There is no value axis of any size to characterise, so every restricted write and every gain part is inside the CIs.

The shares are printed below for completeness, but they mean nothing here:
- input conv holds 10.4% of ‖axis‖², of which 67.8% is gain part;
- dense holds 74.6%.

**Brightness:**
- Scaling the legend plane moves τ monotonically, from 0.15 at ×0.25 to 2.34 at ×3. The net does read the legend, weakly.
- Dimming the objectives plane to ×0.25 raises τ to 5.1, but route-optimality drops to 58%, so that is damage rather than value.

### Verdict
E5 does not test whether the E1–E4/E6 metrics can detect factorisation, because this net has no value computation to factorise. The H1 conclusions on the colour DRC stand exactly as they did before E5, and the missing positive control is still missing.

A side observation, not a claim: with value carried by a separate cue, the DRC learned only a very weak value preference within 212M steps, where the colour nets learn a strong one in 150M.

### Options for a working control
1. **Offline (BC) twin on the legend observation.** Expert routes encode the exchange rate directly, so the model is forced to use value. Cheap, but its axis lives in MLPs, so the comparison is cross-architecture.
2. **DRC on legend with a wider value gap** (e.g. 1.0 vs 0.2) and/or a full 250M schedule at normal LR, so value matters more to return.
3. **A simpler separate cue:** a global per-colour "price" channel, uniform over the whole plane, so value is present at every cell yet is still not a per-object salience.
