# E1: gain-alignment profile and mediation (DRC, novalue11g1 s1234 / s9012 / s3456e, o1 axis)

**Question.** Is the value axis a gain on the colour inputs all the way through the
network (H1), or does its activation change turn into something that isn't brightness
somewhere, with that residual moving the threshold (H2)?

## What was built

- `goalmisgen/analysis/gain_alignment.py`: rebuilds the DRC step from cleanba's flax
  modules so every site can be read and patched (input conv, conv 1, each cell at each
  tick, dense, logits). Also holds the teacher-forced moment accumulator and the
  lockstepped patched rollout, which runs the main, base, write and 4 brightness
  networks together.
- `tests/test_gain_alignment.py`: 5 tests, green on CPU and 4090. They check that the
  step equals `Policy.get_action`, that a zero patch gives the base and a full logits
  patch gives the write, and that brightness fits with R² = 1.
- `scripts/gain_alignment.py`
- Outputs:
  - `results/gain-vs-factorised/gain-alignment{,-lin}-<base>.txt`
  - `E1-tables.txt`
  - `figures/data/gain_alignment/<base>{,.lin}.json`, also on the volume under
    `figures-data/gain_alignment/`

**Definitions.**
- C = ∂h/∂log brightness_c, a central difference with ε = 0.05.
- Δh = the write's central difference at ±offset.
- R² is uncentred, with 2 coefficients per channel.
- Profile: 1024 valid-split levels, teacher-forced along both routes.
- Mediation: 2048 test levels, closed loop. A site group is *set* to base + (full | gain
  component | residual). Coefficients were fitted on the valid split.

## Profile (linearised, offset 0.03), R² per channel, s1234 / s9012 / s3456e

| site | full axis | input conv minus its weight-space gain | random, module-norm matched |
|---|---|---|---|
| input conv | 0.04 / 0.08 / 0.05 | 0.03 / 0.08 / 0.04 | 0.04 / 0.05 / 0.05 |
| conv 1 | 0.08 / 0.17 / 0.19 | 0.06 / 0.10 / 0.10 | 0.08 / 0.09 / 0.06 |
| cell 0 | 0.61 / 0.55 / 0.39 | 0.75 / 0.74 / 0.54 | 0.06 / 0.17 / 0.04 |
| cell 2 | 0.77 / 0.88 / 0.60 | 0.79 / 0.77 / 0.50 | 0.05 / 0.12 / 0.03 |
| logits | 0.90 / 0.95 / 0.68 | 0.89 / 0.88 / 0.62 | 0.07 / 0.26 / 0.01 |

**Plumbing check.** The gain part written into the weights and the same gain applied as
brightness give identical rows, with R² = 1.00 in both convs and 0.94–0.99 in the cells.

**Reading.**
- In the encoder the axis changes activations in ways brightness doesn't (R² at the
  random level).
- From the first cell onwards, 40–90% of its change energy is gain-shaped, far above
  random.
- The 75% of the input-conv slice that is *not* a gain in weight space becomes largely
  gain-shaped once the cells read it.

The brightness column is a colour-1 brightness change matched to the axis's own
threshold shift, a pure-gain positive control. Its matched gains were ±0.5, ±0.4 and
±0.3.

- **Beyond the encoder the axis behaves like brightness.** Its gain-carried fraction
  divided by the brightness control's is:
  - cell 2: 1.12, 0.90, 0.84
  - logits: 1.20, 0.89, 0.90
- **Both flow through cells 0–1 alike.** Full-patch fractions for the axis are
  .60/.55/.17 at cell 0 and .66/.64/.26 at cell 1; for brightness, .47/.45/.13 and
  .53/.50/.26.
- "All but input conv" carries a gain share equal to or larger than the full axis's
  (logits .62/.34/.74).

## Verdict for this experiment

**Leans H1.**
- No part of the axis beyond the encoder can be told apart from a colour-brightness
  change of the same behavioural size.
- Its activation change in the planner is mostly gain-shaped.
- It isn't only brightness at the input: the encoder does something else, which the
  cells then read as gain.

## Caveats

- **Gain/residual is not a clean split beyond conv 1.** Even pure brightness has only
  26–61% carried by its gain component, because the coefficients are fixed and C is a
  derivative applied at a large dose. Read these numbers against the brightness column,
  not against 1.
- **Late sites are uninformative.** The logits and dense layer are bottlenecks, so
  alignment there is expected under either hypothesis. The informative rows are cells
  0–2.
- **E1 cannot rule out one form of H2.** A separate value variable whose downstream
  effect happens to look like salience would pass. E2 and E3 are needed for that.
- **s3456e is weaker everywhere,** and it barely mediates through cells 0–1.
- **Scope:** o1 axis only, DRC only. ResNet, ViT and BC were not run.
- **Bug, now fixed:** in the runs for s1234 and s9012 the brightness control's "write
  threshold" line was wrong, because the main network didn't apply the observation
  gains. All fractions above use the full logits patch as the denominator, which is
  exactly the write (tested). The script is fixed and s3456e ran with the fix.
